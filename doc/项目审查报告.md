## P1 — 下一版必须修（2026-09-13 全部完成 ✅）

### P1-3 手机窗与角色切换脱节（确认 bug）✅ 已修 `b38132a`

**证据**

- `GameMain._ready` L106-112 只创建一次 `_phone_overlay` 并接线；
- `GameMain._apply_character` L355-363 更新小人 / 立绘 / 状态 / 互动菜单，**不触碰手机窗**；
- `phone_overlay._ready` L34-45 只读一次 `GameManager.get_current_char_id()` 并构建 `_messages`；`open_overlay()` L47-54 不刷新。

**后果**：切换角色后打开手机，窗口标题、人设、名字、上下文仍是旧角色，消息与好感也记录到旧 `char_id`（P4 多角色与 P0 手机两个卖点互相破坏）；另外手机上下文是**启动时快照**，本局电脑聊天的内容不会进入手机上下文。

**修复**：给 `phone_overlay` 增加 `set_character(char_id)` + `reload_context()`；`_apply_character` 中调用；`open_overlay()` 时若角色变化则重建 `_messages`。

### P1-4 离线结算切人竞态（确认 bug）✅ 已修 `b38132a`

**证据**：`GameMain._run_offline_ai_settlement` L1050-1065 捕获 `char_id` 构建上下文，但 `_on_offline_settled` L1068-1085 全程使用 `GameManager.CURRENT_CHAR_ID` / `_char_name()`。请求发出后等待网络期间玩家切换角色 → 结算消息、状态修正、好感全部落到**新角色**上。

**修复**：请求时 `bind` 捕获 `char_id`，回调内全部按该 id 读写（状态 / 好感 / 记忆 / 台词名）。

### P1-5 AIConnector 单飞行 + 全局错误信号 ✅ 已修 `419058a`

**证据**

- `AIConnector` L16-19 用单份 `_pending / _mode / _on_success / _on_error`；L46-48 并发请求直接失败；L88 `error_occurred.emit` 全局广播，`chat_screen` L31 订阅。
- 具体复现：启动后 0.6s 离线结算占用请求（`GameMain` L132、L1045），玩家立刻打开聊天发消息 → 只得到"上一次请求还没完成，请稍等"。
- 次要：`HTTPRequest.timeout = 20s`（L11/24）对长回复偏短，且无重试。

**建议**：改为 FIFO 请求队列 + 每请求独立上下文对象（模式/回调/角色 id）；错误只走所属请求的回调，全局信号降级为日志；超时改为可配置。

### P1-6 聊天每轮两次 API 请求 ✅ 已修 `1648ef9`

**证据**：`chat_screen` L65 发正文、回复后 L92 再发一次好感判定；判定期间 L81-82 锁住输入。而 `phone_overlay` L104-117 已是一次结构化返回 `{reply, affection, mood_delta, ...}`。

**影响**：聊天成本翻倍、延迟增加、UI 被锁；两条链路行为不一致（判定失败文案、心情变更规则都各写一份）。

**建议**：聊天统一改为一次 JSON 返回正文 + 好感 + mood_delta；失败时降级为不加好感并照常显示正文。

### P1-7 《正式角色计划》替换清单不完整 ✅ 已修（main.tscn 去硬引用 + 清单补全）

**证据**：`scenes/main.tscn` L5 直接以 `ext_resource type="Texture2D" path="res://assets/chars/char_03/portrait.png"` 引用旧素材（删除 `char_03` 后场景将缺资源），L151 `StatusLabel.text = "梅尔"` 也是硬编码——二者均未出现在 `doc/正式角色计划.md` §5 清单中。此外 `data/config.json` 的 `active_char:"char_03"`、`data/memory.json` 的 `char_03` 分区也未被提及。

**建议**：把 §5 从"文件罗列"改为"`grep -rn "char_03\|梅尔"` 全仓库扫描 + 逐项确认"的检查清单，并明确 `main.tscn` 需改纹理引用与默认文案；§6 版权清理补"完成定义"（Release 已删/替换、历史已重写、pck 扫描通过、README 更新）。

> **约定**：本文档记录 AIHome 的产品定位、核心玩法与后续功能计划。
> 需求来源：用户口述（2026-08-30），助手逐条追问并确认；未经确认的项标注【待确认】。
> 实现进度以 README「当前功能」为准；早期设计稿（`doc/aihome描述.md`、`doc/aihome具体.md`）部分内容已被本规划取代或调整。

## 1. 项目定位

让一个 AI **生活在这个房间里**，玩家以「养宠物的主人」的身份与它相处：

- **角色有自己的生活**：自主行动（闲逛、自己使用家具、按时间作息、有自己的内部状态与心情）
- **玩家可以影响角色**：吸引它移动、和它一起玩小游戏、发消息看它的反应、引导它做日常互动
- **核心是「自主 + 可被影响」**：影响是**引导**而非**控制**——角色不是被遥控的像素小人，而是有自己的想法、会主动回应玩家的"室友/宠物"

**一句话卖点**：养一只住在像素房间里、会自己生活、也会回应你的 AI 小伙伴。

### 体验基调

- 温馨、陪伴感、生活气息（延续现有暖色像素风）
- **房间是共同生活空间**：所有互动都发生在可见的房间里；即便用手机聊天，也不能把房间完全挡住
- 角色气质：**「似人非人」的二次元角色感**——有人的需求（吃东西、会累、有心情），但又不是完全的人类，保持二次元角色的可爱与神秘感

## 2. 玩家互动方式（四种）

### 2.1 吸引 AI 移动

- **形式**：点击引导 + AI 主动靠近（点击地板/家具/角色作为引导，角色主动寻路过去并带反应动作）
- 区别于现有「点击地板 → 角色寻路」：要把角色表现为**自愿被吸引**（带动机、反应动作），而不是盲从指令
- 吸引的细化表现（被吸引动画、被拒绝/走神时的行为等）【待确认】

### 2.2 电脑小游戏

- 与 AI 角色在电脑上一起玩各种小游戏（现有：15×15 AI 五子棋 + 游戏选择界面）
- 可继续扩展游戏库；游戏结果与好感度挂钩（现有：胜 +3 / 平 +1 / 负 0）
- 下一款小游戏选型、是否都做成"和 AI 对战"【待确认】

### 2.3 手机消息（新功能，重点）

**入口与样式（已确认）**
- 入口：**玩家界面侧边栏图标**，位于「设置」键下方；**设置键与手机键都改为图标**（不再用文字）
- 手机仅用于**聊天 + 影响角色**，**只有一个页面**（半透明竖屏聊天窗），不做多余功能
- 对话只占一部分屏幕，**房间与角色仍然可见**

**场景与反馈（已确认）**
- 随时可聊：不限于电脑前，玩家随时可以给角色发消息
- 角色收到消息后：
  1. 消息提示音
  2. 角色**气泡**显示反应（文字/情绪）
  3. 对应**动作动画**（角色会动起来）

**影响 AI 的方式（已确认：交给 AI 决定）**
- 玩家消息/请求 → AI 可返回**结构化格式**（如 JSON 指令）或**调用工具**（工具调用/function calling）来操控角色
- 例：AI 返回"移动到电脑前/去吃东西/做某个动作"等指令，由游戏侧调度器执行；具体指令协议（指令集、参数、校验）在实现阶段细化【待确认】

**与电脑聊天的关系：并存，各有侧重（已确认）**
| 入口 | 对话形式 | 角色动作 |
|---|---|---|
| 电脑聊天 | 整屏大对话（可查历史/记忆/日记联动） | 无动作，纯聊天 |
| 手机消息 | 半透明小窗轻量消息 | 提示音 + 气泡 + 动作动画 + 可影响动作 |

**数据与记忆（已确认）**
- 手机消息**同样存入记忆 / 日记 / 好感度**（与电脑聊天同一角色，统一对待；其他互动同理）

**实现要点（草案）**
- 消息链路复用现有聊天/AI 接线（AIConnector、记忆、好感度）
- 气泡/动作与现有角色状态机、动画系统衔接
- 手机小窗与电脑 OS、全屏浮层的共存规则（拟议：手机入口仅出现在主界面侧边栏，进入电脑 OS 后不可开，遵循现有无叠加约定）【待确认】

### 2.4 吸引角色进行其他互动

- 以现有家具交互为基础（床/书架/椅子/电视柜/沙发/落地灯/盆栽等），扩展为更主动的日常互动
- 与状态系统联动：玩家的照顾/陪伴会改变角色状态，角色行为随之变化
- 具体互动条目与状态效果【待确认】

## 3. 自主行为系统（新）

玩家不在场/不操作时，角色有自己的生活：

1. **自主闲逛/转悠**：随机走动、去窗边、在房间里转悠
2. **自主使用家具**：累了去沙发/床上休息、无聊去开电脑、饿了找吃的……
3. **时间驱动日程**：按时间安排行为（白天活跃、晚上休息……）
4. **好感度联动**：好感度影响亲近/害羞程度、被吸引的意愿、是否主动靠近玩家
5. **被吸引时的响应**：玩家吸引/发消息时，有明确的响应与反应动作

> 实现方向：由内部状态（见 §4）驱动行为选择，行为调度器负责任务切换；具体行为权重与日程表【待确认】。

## 4. 状态系统（新）

- **纳入规划**：角色有内部状态，用于驱动自主行为与互动表现
- **状态维度（已确认）**：
  - **饱食/饥饿**：饿了会去找东西吃（吃东西作为主要表现之一）
  - **心情**：会在聊天时被感受/影响（聊天内容影响心情变化）
  - **疲惫/精力**：会累，累了去休息
- **数值 UI 后置**：先做内部状态与行为驱动，不做显式数值面板（可二期再做）
- 状态随时间/行为/玩家互动变化，影响行为选择；表现需贴合**「似人非人」的二次元角色感**
- 状态的具体数值范围与变化规则【待确认】

## 5. 与现有系统的关系与改造点

| 现有系统 | 变化 | 说明 |
|---|---|---|
| 点击地板寻路 | 改造 | 从"命令移动"变为"吸引移动"（角色带动机/反应） |
| 电脑聊天 | 保留 | 纯聊、整屏、角色无动作 |
| 电脑小游戏 | 保留 + 扩展 | 游戏库可继续扩充 |
| 好感度 | 保留 + 联动 | 参与状态/行为/亲近度表达；手机消息同样适用 |
| 记忆 / 日记 | 保留 | 手机消息与其他互动**同样计入**记忆/日记/好感度（同一角色统一对待） |
| 家具交互 | 保留 + 增强 | 接入状态系统与"吸引力" |
| 设置入口 | 小改 | 文字按钮改为**图标** |
| 布置台 / 新手攻略 / 立绘 | 保留 | 暂不变 |

## 6. 建议分期路线图（已按用户意见调整）

- **P0 手机消息最小闭环** ✅ **已实现（2026-08-30）**：手机图标入口（设置图标下方）→ 半透明竖屏聊天窗（单页）→ 发消息 → AI 回复 + 气泡 + 提示音 + 简单动作动画；AI 结构化输出（JSON：`reply/emotion/action/affection/reason`）影响角色动作（走向家具或 wave/hop/sad）；电脑聊天保持纯聊
- **P1 吸引移动改造** ✅ **已实现（2026-08-30）**：点击引导 + AI 主动靠近（点击处放置吸引物 → 停顿 + 头顶「！」 + 小跳反应后自愿寻路）；好感度影响响应概率（≥70 必应 / ≥50 90% / 其余 75%），走神冒「？」；点击家具到达后自动触发交互；已去掉路径线与目标十字标记
- **P2 自主行为 + 状态系统（合并实现）** ✅ **已实现（初版，2026-08-30）**：自主闲逛 + 自主使用家具 + 时间日程 + 好感度联动 + 被吸引响应；内部状态（饱食/心情/疲惫）驱动行为，数值 UI 后置；新增冰箱/厨具/饭桌；离线 AI 结算；细节按 §7 P2 落地规则实现，可后续调参
- **P3 扩展 ✅ 已完成（2026-08-30 定稿并实现）**：游戏库扩展（**Graphwar 仿函数对打 ✅ + 井字棋 ✅**；21点/贪吃蛇后置 P4）、**其他互动细化**（**5 条 ✅ 初版**，角色文件数据驱动）、**立绘差分表情**（**6 档 ✅**）；**多角色切换顺延至 P4**。落地规则见下方 §7「P3 落地规则」

> **P3 已全部实现完毕（2026-08-30）**：Graphwar 多球版、井字棋、立绘差分 6 档、其他互动 5 条（角色文件数据驱动）；后续进入 **P4**（多角色切换、21点/贪吃蛇、多方向行走动画、BGM/TTS 等，细节下会话再对齐）。

## 7. 已确认 / 待定汇总

### 已确认（2026-08-30）

- 项目定位：AI 生活在房间，玩家如主人；**自主 + 可被影响**
- 四种互动：吸引移动（点击引导 + 主动靠近）、电脑小游戏、手机消息、其他互动
- **手机消息**：
  - 入口在侧边栏「设置」图标下方，手机为图标；设置键也改为图标
  - 半透明竖屏聊天窗、单页、随时可聊；提示音 + 气泡 + 动作动画
  - 影响 AI 的方式**交给 AI 决定**（返回结构化格式 / 工具调用操控角色）
  - 同电脑聊天**并存**（电脑=纯聊无动作）；手机消息与互动**同样计入记忆/日记/好感度**
- 自主行为：闲逛 / 自主用家具 / 时间日程 / 好感度联动 / 被吸引响应（全选）
- 状态系统：纳入；维度=**饱食/心情/疲惫**；数值 UI 后置；表现「似人非人」的二次元角色感
- 分期：**P0 手机消息 → P1 吸引移动 → P2 自主行为+状态系统（合并）→ P3 扩展**
- **P0 落地规则（2026-08-30 按拟议实现并确认）**：
  - 手机小窗与电脑 OS 共存：入口仅主界面侧边栏（「设置」图标下方），电脑 OS/全屏浮层打开时不可开
  - AI 动作指令协议（P0 版）：结构化 JSON `{"reply","emotion","action","affection","reason"}`；`action` ∈ `wave|hop|sad|none|sleep|read|sit|watch|rest|light|water|computer`（后 8 项 = 走向对应家具并触发交互）
  - 消息提示音：`assets/sfx/notify.wav`（轻快双音提示音）；气泡：角色上方短气泡（限 36 字）；动作动画：角色 sprite 轻量 Tween（wave 摆头 / hop 跳两下 / sad 低头）
  - 消息接收节奏（2026-08-30 用户补充）：发送 → 延迟 `RECEIVE_DELAY=1.0s` → 角色收到（提示音 + 头顶「！」特效 + 顶部通知横幅「梅尔 收到了新消息」）→ 停顿 `REPLY_DELAY=0.8s` → AI 返回回复；期间系统提示不插入聊天流，改为手机右上角逐条队列显示（滑入/停留/淡出）
  - JSON 容错（2026-08-30）：`AIConnector` 去掉 Markdown 围栏 + 括号配对提取最外层 JSON，失败打印原文到控制台；手机/电脑两端的 AI 提示词改为严格 JSON + 示例，`affection` 支持多形式归一化（true/是/1/对/加分），判定失败不阻塞对话
- **P1 落地规则（2026-08-30）**：
  - 点击地板/家具 = 「引导」而非命令：点击处放置**吸引物**（预置 6 种：爱心/小鱼干/苹果/星星/毛线球/书卷；设置「通用」可固定或随机，默认随机；`general.attract_item`），物品上下漂浮
  - 反应：先停下 + 头顶「！」特效 + hop 小跳，停顿 `ATTRACT_AFTER_DELAY=0.4s` 后自愿寻路；到达物品格后物品消失
  - 好感度影响响应概率：≥70 → 100%；≥50 → 90%；其余 → 75%；不走时头顶「？」气泡并原地不动
  - 点击家具：到达旁边后自动触发交互（不再需要点两次）
  - 已移除原目标十字标记与寻路路径线（`_draw_target` / `_draw_path`）
- **P2 落地规则（2026-08-30 用户逐一确认定稿）**：
  - **1 时间**：现实时间（系统钟点），不做虚拟时钟；日程按现实钟点分段（06–18 活跃 / 18–22 渐缓 / 22–06 倾向休息发呆）
  - **2 进食**：新增家具 冰箱（拿食物）/ 厨具（做饭）/ 饭桌（吃饭）；链路=冰箱拿食物 → 可直接吃（饱食 +20）或厨具做饭（饱食 +35、心情 +2）→ 在饭桌吃；**沙发也能吃**；食物为表现性状态，不做复杂库存 UI
  - **3 自主用电脑**：走到电脑旁坐下，不自动弹 OS；电脑旁弹出「一起玩」按钮（仅自主用电脑时出现），点击直接打开电脑面板并进入游戏选择，关闭面板即收起
  - **4 浮窗共存**：手机等小浮窗打开时自助行为**照常**；电脑 OS / 全屏浮层打开时暂停自助行为；玩家任何输入立即打断自主行为
  - **5 状态数值**：饱食/心情/疲惫 0–100（初始 70/60/30）；**在线缓慢**（约现实 10 分钟 ±1，倍率可调）；离线 AI 结算是主要变化；阈值：饱食 <30 找吃的、疲惫 >75 去休息、心情 <30 表现低落且更易走神；**测试倍率**：设置→通用「状态变化速度 ×1/×5/×10」（`general.dev_state_speed`，代码注释：测试用，正式版移除）
  - **6 行为权重/日程**：状态阈值优先 → 随机闲逛；同目标不连续去两次（冷却）；三段日程如上
  - **7 状态感知**：纯表现（行为 + 偶尔气泡"好困…""没胃口"），**不加任何数值 UI**
  - **8 好感度体现**：不在行为上做明显差别；把好感度描述注入聊天上下文（人设提示），AI 聊天中轻微体现（更亲近/更冷淡）
  - **9 自主好感**：每次完成正式自主行为（进食/睡觉/玩电脑/看书/看电视等，不含闲逛）50% 概率 +1，**同一自然日上限 +3**；自主行为记日记
  - **10 心情**：聊天 AI 返回可选 `mood_delta`（-2~+3，缺失按 +1），手机/电脑统一应用
  - **11 离线结算**：上线时若离线 ≥30 分钟（测试倍率可加速），按现实时间模拟离线变化；**情绪/数值变化交给 AI**——提示词带离线时长、当前状态、人设、记忆摘要，输出 JSON：`{"satiety":-X,"fatigue":+X,"mood":+X,"affection":0或1,"message":"..."}`，一次性应用（0–100 钳制），message 作为角色提示/气泡，affection 计入当日自主好感上限

### P3 落地规则（2026-08-30 确认）

- **范围**：游戏库扩展 + 其他互动细化 + 立绘差分表情；**多角色切换顺延至 P4**（P3 只在存档/角色接口上预留结构；已于 2026-09-04 完成，见 §7「P4 落地规则」）
- **游戏库**：统一「与 AI 对战」，胜负沿用通用规则（胜 +3 / 平 +1 / 负 0）
  - **P3 两款**：① **Graphwar 仿·函数对打（✅）** ② **井字棋（✅）**
  - **P4 两款**：21点/纸牌（✅ 已实现 2026-09-04）、贪吃蛇/益智（✅ 已实现 2026-09-04）
  - **井字棋（✅ 已实现 2026-08-30）**：3×3 与 AI 对战（玩家 X / AI O）；AI 策略=能赢先赢→堵玩家→中心→随机角→任意（非完美博弈，玩家可赢）；胜负沿用通用规则
  - **Graphwar 仿·函数对打（✅ 已实现 2026-08-30；按用户反馈多轮改版为多球版）**：
    - 双方各 3 个球（玩家左侧蓝菱形 / AI 右侧红圆，每轮 y 随机），每回合点选自己一个球发射（**发射不消耗，仅被击毁才消失**）；**先击毁对方全部 3 球获胜**
    - 玩家**直接输入函数 f(x)**（x = 离开出发点的水平距离），炮弹从该球出发沿「y = 球高度 + f(x) − f(0)」飞行（曲线相对出发点，起点固定；**轨迹随炮弹逐步显示**）

### P4 落地规则（2026-09-04 确认；多角色切换 ✅ + 21点 ✅ + 贪吃蛇 ✅ 已实现）

  - 显示器外框 / 桌面 / 标题栏 / 任务栏
  - 子界面在同一 ScreenArea 内切换，不叠加
  - OS 屏幕切换 API（FADE / SLIDE_* / SCALE + 导航栈）
- 游戏选择界面（当前含五子棋，可继续加游戏）
- 标准 15×15 AI 五子棋（结果面板、退出键、胜负钩子预留）
- 聊天：已实现聊天界面 + OpenAI 兼容接口 + 记忆持久化 + 好感度判定（需在设置里配置 API）
- 设置：已实现标签页设置界面（通用/显示/音频/AI 设置）
- 左侧角色立绘叠加层已实现，当前初始角色为 char_03 梅尔；角色资源已规范为标准格式（见 assets/chars/README.md）
- 记忆系统：聊天历史持久化（短期 40 条 + 按日期归档）、长期摘要 + key_facts（AI 提炼，失败降级规则）
- 好感度系统：0-100，每日记录变化原因；聊天 AI 判定每日上限 10、五子棋胜 +3/平 +1/负 0、家具互动每种每日首次 +1
- 日记：已实现电脑内应用，按日期自动整理当天聊天/互动/好感度变化（仅自动整理，无手动编辑）
- 房间布置：已新增「布置台」家具（交互 decorate，不加好感度），长按家具拾起→移动→点击放下，保存到 `user://room_layout.json`，可恢复默认（早期设计稿“房间编辑器”的简化版）

## 用户确认结论（2026-08-29）

### 已确认方向

1. **聊天模块**：接入真实 AI API，采用 **OpenAI 兼容接口**（用户填写 Base URL / API Key / 模型名）。
2. **日记 / 好感度系统**：已实现（2026-08-30 对齐）。规则：日记为按日期自动整理（仅自动整理，无手动编辑）；好感度来源：聊天由带人设的 AI 按对话内容判定是否加分（每日上限 10）、五子棋胜 +3/平 +1/负 0、家具互动每种每日首次 +1。记忆与好感度是日记素材，日记可调用记忆生成。
3. **视觉布局**：保留早期设计 —— **左侧二次元立绘差分 + 右侧 4 方向像素房间**。
4. **立绘 / 表情 / 多角色**：需要做（差分表情、表情库、角色切换等）。
5. **角色状态与权重寻路**：用户单独回答为“**以后再说**”，暂缓；与优先级勾选冲突时以此回答为准。

## 待与用户确认的需求点

### 1. 聊天模块
- 是否接入真实 AI API？
- 使用哪种接口：OpenAI 兼容 / DeepSeek / Ollama 本地？
- 聊天界面是否做成电脑系统里的一个“应用”？
- 是否需要设置页（Base URL / API Key / 模型列表）？

### 2. 日记 / 好感度
- 日记需要记录哪些内容？（好感度、重要对话、成就、角色状态？）
- 好感度怎么变化？（聊天、游戏胜负、日常互动？）
- 是否需要在电脑系统里做一个“日记应用”？

### 3. 游戏模块
- 下一款小游戏做什么？
- 游戏是否都要“和 AI 对战”？
- 游戏是否影响好感度/奖励？

### 4. 角色与视觉
- 是否保留早期设计的“左侧二次元立绘 + 右侧像素房间”布局？
- 是否做差分表情、视线跟随？
- 角色是否需要多角色切换？

### 5. 早期玩法
- 状态数值（饱食 / 精力 / 心情 / 好奇）是否保留？
- 权重寻路（时间 / 状态 / 用户行为影响走路偏好）是否要做？
- 家具交互触发状态恢复（睡觉/吃东西/休息）？

### 6. 平台与发布
- 目标平台：仅 Windows？还是 Linux / Steam Deck？
- 是否考虑 Web 版？

### 7. 语音与辅助
- TTS / 语音播放是否纳入当前计划？
- 是否需要背景音乐 / 音效？

### 8. 编辑器与扩展
- 房间编辑器（可视化拖拽）是否保留？
- 多房间、Mod 加载新角色是否保留？

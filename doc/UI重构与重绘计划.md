## 1. 背景与现状问题

- 当前所有 App 屏（游戏/聊天/日记/设置等）大量使用**手写绝对坐标**（`*.tscn` 中 `offset_*` 硬编码），布局假定 480×360 主画布。
- 电脑 OS 的实际屏区（`computer_panel` 的 `ScreenArea`）约为 **432×268**（面板上下有标题栏/任务栏），手写坐标一旦内容变多就**超出屏区且无法滚动**。
- 已发生问题（2026-09-04）：游戏选择界面新增「21点」按钮后，尾部按钮超出屏区、无法滚动。
  - **已修复**：`game_select.tscn` 改为 `ScrollContainer + VBoxContainer` 滚动列表（按钮 36px、可自由增长）。
- 同类隐患：主界面侧边栏按钮、角色选择浮层、手机小窗、帮助/设置/布置浮层等均有固定尺寸假设；后续新增内容容易再次溢出。

## 2. 重构与重绘目标

1. **统一布局体系**：全部界面改为「锚点 + 容器（VBox/HBox/Grid）+ 主题常量」，**禁止新增手写绝对坐标**；以容器实际尺寸自适应，不再假设固定画布。
2. **屏幕自适应**：电脑 OS 内所有 App 以 `ScreenArea` 为容器 100% 填充（已有 `_prepare_screen` 基础），内部用锚点/容器自适应；F11 全屏下继续走 `canvas_items` 拉伸不发虚。
3. **数据驱动 UI**：
   - 游戏中心改为「游戏注册表」驱动（`id/name/desc/scene`，如 `data/games.json` 或脚本常量表），新增游戏只加配置项，自动生成按钮/滚动列表。
   - 角色选择浮层已由 `CharacterCatalog` 驱动，可作参照。
4. **组件化复用**：抽取通用控件并复用——标题栏、状态栏、可滚动按钮列表、结果弹窗（胜/平/负 + 好感度）、卡片/牌面绘制、关闭/返回按钮。
5. **统一视觉主题**：建立全局主题（`theme.tres`）与样式常量——暖色像素风配色、标题栏/面板边角、按钮常态/按下/悬停、滚动条样式、字体大小层级；各浮层统一半透明底 + 圆角 + 暖金描边。
6. **操作反馈**：滚动条/滚轮/触摸滚动、按钮可用态与禁用态、tooltip 齐全；关键操作状态栏提示。

## 3. 建议的实施顺序

1. **基础规范**：定基准分辨率、布局常量、主题资源（theme.tres）、通用 StyleBox；先让「电脑 OS 外壳」锚点自适应。
2. **游戏中心重构**：改为注册表驱动 + `ScrollContainer` 列表（本次已铺路：列表可滚动，后续把按钮生成改为数据驱动）。
3. **通用组件抽取**：`CommonTitleBar` / `CommonStatusBar` / `ResultPanel` / `ScrollButtonList` 等，替换重复代码。
4. **逐个 App 重绘/适配**：游戏各屏（五子棋/Graphwar/井字棋/21点）→ 聊天 → 日记 → 设置 → 手机 → 帮助/布置 → 角色浮层。
5. **回归与验收**：每个界面 headless 冒烟 + 手动检查 480×360 与全屏窗口；保证多角色动态文案、好感结算、手机通知等既有功能不回归。

## 4. 范围边界与约束

- **功能优先**：P4 功能项（贪吃蛇、多方向行走动画、BGM/TTS）继续正常推进，不被 UI 重构阻塞；两者并行时每次小步提交。
- **兼容性**：保留 `computer_panel` 的 `open_*`/`go_back` API 与各屏信号（back_requested / finished / restarted），保证 GameMain 接线无需大改。
- **多角色回归**：所有「梅尔」硬编码已改为动态显示名（`CharacterCatalog.get_display_name`），重绘时不得改回硬编码。
- **验证习惯**：`user://config.json` 挪开后再冒烟，防止触发真实 API；新增场景/资源先 `--headless --import` 再运行。
